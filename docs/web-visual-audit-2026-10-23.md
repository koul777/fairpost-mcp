## 보강한 검사가 놓친 이유와 확인

P1, P2, P4는 이전 두 실행에서 자동 검사를 모두 통과했고 화면 판독 역할이 찾았음. 이유는 세 가지임. 생성 글자 검사가 `counter()` 숫자를 건너뛰었고, 입력 칸 글자는 표시 층이 아니라 입력 칸 자체의 글자라 표시 층 대비를 재는 검사가 없었고, `::selection`은 검사 대상이 아니었음. 이를 보강한 뒤에도 R1이 남았는데, 선택 색을 입력 칸 바탕 위에서만 재서 고른 표시 채움 위에 겹친 경우를 놓쳤기 때문임. 이제 선택 색을 모든 표시 채움 위에 겹쳐 재는 검사를 추가함.

보강한 검사를 수정 전 스타일에서 돌려 실제로 걸리는지 확인함. 같은 검사를 git HEAD(`f39a2ed`)의 `styles.css`, 통합 커밋 `0cffa4a`의 `styles.css`, 현재 스타일에 대해 어두운 모드와 밝은 모드로 돌림(3개 화면 상태와 책 진입 화면).

| 스타일 | 어두운 모드 실패 | 밝은 모드 실패 |
|---|---|---|
| git HEAD | 25건(숫자 배지 17건, 고른 표시 1건, 선택 색 1건 3.99:1, 표시 위 선택 6건) | 0 |
| 통합 커밋 `0cffa4a` | 6건(고른 표시 위 선택 3.25:1, 나머지 표시 위 선택 4.18:1, 합 6곳) | 0 |

화면 판독 역할이 데스크톱 모두 펼침 캡처의 y 약 16,400px 아래가 비어 있다고 알림. 같은 상태를 전체 화면 캡처(1366x24934)와 스크롤 위치별 화면 크기 캡처 30개(마지막 실행 기준, 처음 재현은 28개)로 찍어 비교해 재현함.

- 전체 화면 캡처는 y 16,200 근처부터 22,500 근처까지 8개 구간에서 스크롤 캡처와 달랐음(마지막 실행은 y 16,580부터 22,383까지 8개). y 17,100 근처에서 전체 화면 캡처는 흰 화면이고 스크롤 캡처에는 '정보·설명과 접근' 질문 묶음이 그려져 있음.
- 원인은 레이아웃이 아니라 Chromium의 전체 화면 캡처 한계(약 16,384px)로 판단함. 스크롤 캡처에서는 같은 구간이 모두 그려짐.
- 검사 도구는 이제 15,000px보다 긴 화면을 스크롤 위치별 캡처로 찍고 구간마다 빈 화면인지 검사함. 이번 실행에서 12곳, 360개 구간 모두 비어 있지 않음. 2차 판독의 권고에 따라 구간끼리 겹치게 찍었음. 데스크톱·태블릿은 고정 이동 막대 높이(66px)에 여유를 더한 71px씩 겹쳐 경계 띠가 빠지지 않음. 모바일은 막대 높이를 0으로 재서 겹침이 50px뿐이라 경계 162곳((45-1 + 38-1) x 2 모드)마다 약 16px가 어느 캡처에도 보이지 않음. 3차 판독이 찾은 검사 도구 문제이며 제품 결함이 아님. 고치려면 모바일 배치의 고정 막대에 선택자를 맞추거나 막대 높이를 못 잴 때 겹침 기본값을 71px 이상으로 두어야 하고 브라우저 재실행이 필요해 아직 반영하지 않음.
