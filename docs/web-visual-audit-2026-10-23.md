## 보강한 검사가 놓친 이유와 확인

P1, P2, P4는 이전 두 실행에서 자동 검사를 모두 통과했고 화면 판독 역할이 찾았음. 이유는 세 가지임. 생성 글자 검사가 `counter()` 숫자를 건너뛰었고, 입력 칸 글자는 표시 층이 아니라 입력 칸 자체의 글자라 표시 층 대비를 재는 검사가 없었고, `::selection`은 검사 대상이 아니었음. 이를 보강한 뒤에도 R1이 남았는데, 선택 색을 입력 칸 바탕 위에서만 재서 고른 표시 채움 위에 겹친 경우를 놓쳤기 때문임. 이제 선택 색을 모든 표시 채움 위에 겹쳐 재는 검사를 추가함.

보강한 검사를 수정 전 스타일에서 돌려 실제로 걸리는지 확인함. 같은 검사를 git HEAD(`f39a2ed`)의 `styles.css`, 통합 커밋 `0cffa4a`의 `styles.css`, 현재 스타일에 대해 어두운 모드와 밝은 모드로 돌림(3개 화면 상태와 책 진입 화면).

| 스타일 | 어두운 모드 실패 | 밝은 모드 실패 |
|---|---|---|
| git HEAD | 25건(숫자 배지 17건, 고른 표시 1건, 선택 색 1건 3.99:1, 표시 위 선택 6건) | 0 |
| 통합 커밋 `0cffa4a` | 6건(고른 표시 위 선택 3.25:1, 나머지 표시 위 선택 4.18:1, 합 6곳) | 0 |
| 현재 | 0건(입력 칸 위 선택 7.9:1) | 0 |

숫자 배지 17건은 서로 다른 배지 10개를 화면 상태 4곳에서 센 값(사용 순서 4, 검토 기록 3, 책 진입 사용 순서 3)이며 측정값은 전부 2.15:1, 고른 표시는 1.36:1로 화면 판독 결과와 같음.
