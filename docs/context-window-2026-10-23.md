# 트리거 문맥 그룹 창 끝 판정 수정 (2026-10-23)

트리거의 `context_groups` 패턴이 후보 주변 창으로 자른 글이 아니라 공고 글 자체를 보고 판정하도록 엔진
(`core/engine.py`, `core/morph.py`, `web/engine.js`)을 고침. 제외 검사 수정(`docs/exclusion-window-2026-10-23.md`,
engine-v6)의 '남은 한계'에 적은 같은 종류의 문제임. 규칙 데이터(`data/`)는 바꾸지 않음.

| 항목 | 수정 전 | 수정 후 |
|---|---|---|
| 규칙셋 버전 | `…-36f30cccacd4` | 그대로 |
| 매칭 버전 | `match-ae2f8b43f9de8d64` | `match-13f5d6e7c53a493f` |
| 엔진 버전 상수 | `engine-v6-…-exclude-window-reads-text` | `engine-v7-…-exclude-window-reads-text-context-window-reads-text` |
| `web/data.js` | | 변화 없음 |

## 문제

`_matches_context_groups`(웹 엔진은 `matchesContextGroups`)는 그룹마다 후보 앞뒤 `window`자를 잘라 그 조각에서
패턴을 찾았음. 조각 끝에서 `$`가 참이 되고 부정 lookahead가 조각 밖 글을 못 봄.

`context_groups`를 쓰는 규칙은 두 개이고 패턴은 17개임.

| 규칙 | 그룹 (창) | 앞뒤 확인이 있는 패턴 |
|---|---|---|
| Q-INFO-012 | `application_form` (5000) | 없음(글자 그대로 5개) |
| Q-INFO-012 | `requested_information` (600) | 5개. `학력사항`, `최종 학력`, `전공명`, `전공:`, `졸업·성적증명서` 뒤에 `무관`, `해당 없음`, `제한 없음`, `기재 불필요` 등이 오고 줄이 끝나면 일치하지 않는 부정 lookahead(안에 `$`) |
| Q-DIST-014 | `qualification_requirement` (600) | 없음 |

그래서 Q-INFO-012만 영향을 받음.

| 창 끝 위치 | 수정 전 | 수정 후 |
|---|---|---|
| `학력사항` 바로 뒤에서 잘리고 창 밖에 `: 무관`이 이어짐 | 학력 정보를 요구하는 것으로 보고 질문 표시 | 창 밖 `: 무관`을 보고 요구로 보지 않음 |
| `최종학력 무관` 바로 뒤에서 잘리고 창 밖에 `한 직무입니다`가 이어짐 | `$`가 창 끝에서 참이라 '무관' 줄로 보고 질문 숨김 | 줄이 이어지므로 '무관' 줄이 아님. 질문 표시 |

## 설계

제외 검사와 같은 규칙을 씀. 패턴 일치는 창 `[left, right]` 안에서 시작하고 끝나야 하고, 앞뒤 확인은 창 밖의 실제
글을 봄. 새 함수 `found_in_window`(`core/morph.py`)가 패턴마다 `_term_in_window`를 부르고, 웹 엔진은 같은 자리에서
`termInWindow`를 부름. 범위 제한 `EXCLUDE_LOOKAHEAD`(1024), 보기(view) 처리, 사전 검사도 제외 검사와 같음.
쓰지 않게 된 웹 엔진 `codePointWindow`는 지움.

## 조사했지만 고치지 않은 것: `source_candidate_allowed`

`core/extractor.py` `source_candidate_allowed`는 후보가 든 문장·절·줄·표 행으로 글을 잘라 보호 표현(`기재 금지`
등)과 반전(`단`, `하지만`)을 찾음. 이 단위는 검토자에게 보여 주는 근거 창(238자) 안으로 일부러 제한한 것이고,
`^`·`$`가 그 단위의 시작과 끝을 뜻하도록 쓴 패턴(`_PROTECTIVE_CONTRAST`, `_PROTECTIVE_DIRECT_GAP` 등)이 있어
제외 검사처럼 글 전체를 보게 바꾸면 뜻이 달라짐. 고정 길이로 자르는 곳은 보호 절 뒤 요구 표현을 찾는
`source[end:clause_end][:60]` 한 곳임. 여기서 `요구(?!\s*하지…않)`가 60자 끝에 걸리면 '요구하지 않'을 요구로
보아 보호 표현을 적용하지 않음(질문·지적을 표시하는 쪽). 이번에는 기록만 함.

## 남은 한계

- 범위 제한 1024: 시작 찾기는 창 끝에서 1024자까지만 보므로, 부정 lookahead 안의 `$`가 그 끝에서 참이 되면 그
  자리를 놓침. 제외 검사에서는 제외하지 않는 쪽(표시)이지만 문맥 그룹에서는 문맥이 없다고 보는 쪽(숨김)이 됨.
  재현: `학력사항`이 창 끝에서 끝나고 공백 1,021~1,022개 뒤 `무관 한 직무입니다`가 이어지면 engine-v7은 숨기고
  engine-v6은 표시함. 한 줄에 공백이 1,000자 넘게 있어야 생기고 train에서는 변화 0. 이 동작을 시험에 고정함.
- `source_candidate_allowed`의 60자 경계(위 절).

## 규칙 동결과의 관계

탐지 패턴·트리거·문맥 그룹은 그대로이고 엔진의 판정 방식만 바뀜. 실제 공고(train)와 이전 합성 입력 세트에서는
결과가 바뀌지 않음. 합성 문맥 창 사다리에서 Q-INFO-012가 숨는 쪽 2,793건, 표시되는 쪽 28건 바뀌므로 채택은
engine-v6와 함께 사용자 판단으로 남김.
