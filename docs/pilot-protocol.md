# FairPost 채용담당자 파일럿 프로토콜

이 파일럿은 질문 카드가 채용공고 게시 전 검토에 실제로 도움이 되는지
확인한다. 법령 표현 정밀도나 부재 탐지 재현율을 측정하는 봉인 홀드아웃
평가와 목적이 다르다. 질문의 발동률이나 파일럿 만족도를 G1ㆍG2 성능으로
보고하지 않는다.

2026-10-04 실행 순서: 사람 라벨링 인력 배정과 동시에 파일럿 참여팀을 확보한다.
초기 대상은 공공기관 채용담당자로 좁히며, 아래 3팀ㆍ20건 기준은 전체 합계다.
참여팀은 아직 미확정이고 실제 결과도 수집되지 않았다.

## 참여팀 전달 안내

다음 안내는 담당자가 참여팀을 확보한 뒤 전달할 초안이다. 자동으로 발송하지 않는다.

> 채용공고 게시 전 검토에 FairPost가 도움이 되는지 확인하는 파일럿입니다.
> 실제 초안을 평소 방식으로 검토한 다음, 정적 웹 또는 로컬 도구로 다시 검토해 주세요.
> 공고 원문은 보내지 않고 검토시간과 질문별 활용 여부만 기록합니다.
> AIㆍ현행 법령 보강은 끈 상태로 진행합니다. 공정성이나 위법 여부의 판정 실험이 아닙니다.

운영자는 3팀에 가명 `pilot-team-a`ㆍ`pilot-team-b`ㆍ`pilot-team-c`를 부여하고
실명 매핑을 내부에만 보관한다. 실제 초안은 우선 7ㆍ7ㆍ6건으로 배분하되 팀별 업무량에
맞춰 조정한다. 각 사례에는 고유한 `case_id`를 부여해 중복 집계를 막는다.

## 담당자 진행 순서

1. 평소 검토 방식의 소요시간을 별도 기록한다. 이것은 현재 집계기의 필수 필드가
   아니므로 피드백 JSONL에 임의 필드를 추가하지 않는다.
2. 공고를 입력하고 첫 검토를 실행한다. 원문이나 화면을 외부로 보내지 않는다.
3. 문구를 수정하고 다시 검토해 `수정 전후 비교`를 확인한다. 표시가 사라진 항목도
   수정의 적절성은 직접 확인한다. 다른 공고로 넘어갈 때는 `지우기`를 누른다.
4. 전문가 모드의 질문과 메모에 나온 질문 ID를 기준으로 **첫 검토부터 마지막 검토까지
   표시된 질문의 합집합**을 질문당 한 번씩
   `actionable`ㆍ`relevant_no_action`ㆍ`irrelevant` 중 하나로 기록한다.
   도움이 된 질문만 선택해 기록하지 않는다.
5. `examples/pilot_feedback.example.jsonl`의 형식으로 사례 1건당 한 줄을 작성한다.
   예시는 합성 자료이므로 실제 결과 파일에 섞지 않는다. 결과 파일은
   `.private-review/pilot-feedback.jsonl`에 보관한다.
6. 아래 집계 명령을 실행한다. 비교 기능 자체의 불편은 운영자가 로컬 메모에 기록하고,
   공유 보고서에는 원문ㆍ자유서술 없이 개선 과제만 정리한다.

## 범위와 개인정보 경계

- 3개 이상 독립 채용팀이 실제 초안 20건 이상을 정적 웹 또는 로컬 CLI로
  검토한다.
- 공고 원문은 담당자의 브라우저 또는 컴퓨터 밖으로 보내지 않는다.
- 입력 JSONL에는 가명 `case_id`, `team_id`, 정량값과 열거형 응답만 둔다.
- 조직명, URL, 사람 이름, 연락처, 공고 원문과 자유서술은 수집하지 않는다.
- 보고서는 팀ㆍ사례 식별자를 제거한 집계만 보존한다.

## 한 사례의 기록

`examples/pilot_feedback.example.jsonl`의 각 행은 다음을 기록한다.

- 검토에 걸린 분
- 표시된 질문별 `actionable`, `relevant_no_action`, `irrelevant`
- 최종 결과 `edited`, `confirmed`, `escalated`, `no_action`
- 면책문 이해 여부
- 로컬 전용 처리 확인
- 실제 사용한 규칙셋ㆍ매칭 버전

질문이 표시되지 않은 사례도 `question_feedback: []`로 기록할 수 있다.
도구는 현재 사전에 없는 질문 ID와 현재 버전이 아닌 행을 거부한다.

## 초기 통과 기준

```powershell
python tools\summarize_pilot_feedback.py `
  --input .private-review\pilot-feedback.jsonl `
  --output reports\pilot_summary.json `
  --min-cases 20 `
  --min-teams 3 `
  --max-median-minutes 10 `
  --min-actionable-case-rate 0.70 `
  --max-irrelevant-question-rate 0.20
```

통과 기준은 중앙 검토시간 10분 이하, 실행 가능한 사례 70% 이상, 무관
질문 20% 이하, 면책문 이해와 전 사례 로컬 처리다. `alert`는 실패를
숨기지 않고 종료 코드 `2`를 반환한다. 파일럿 시작 전에 조직의 실제
업무량과 검토 단계에 맞춰 임계값을 승인하고 변경 이력을 남긴다.

## 해석

- `actionable`은 해당 질문이 공고 수정, 내부 확인 또는 상위 검토로
  이어졌음을 뜻한다.
- `relevant_no_action`은 질문은 적절했지만 기존 절차가 이미 충족됐음을
  뜻한다.
- `irrelevant`는 현재 공고 또는 채용 절차와 관계가 없음을 뜻한다.
- 파일럿 결과가 통과해도 공정성, 적법성 또는 시장 전체 일반화를
  증명하지 않는다.
- `actionable_case_rate`는 하나 이상의 질문을 `actionable`로 평가한
  사례만 센다. 질문이 표시되지 않은 채 다른 이유로 수정한 사례는
  `non_no_action_outcome_rate`에는 포함되지만 질문 유용성에는 포함되지 않는다.
