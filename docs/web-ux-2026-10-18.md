# 웹 화면 개선 기록 (2026-10-18)

브랜치: `agent/2026-10-18-web-ux` (기준 `main` 0fa7396)

## 목표

검토 흐름 **붙여 넣기 → 검토 → 고치기 → 다시 보기 → 저장**에서 사람이 덜 헤매게 한다.
표현 카드가 공고문의 어디를 가리키는지 바로 보이게 하고, 표현에서 담당자가 답할 질문으로
바로 이어지게 하며, 결과를 점수판처럼 읽지 않게 한다.

## 지킨 것

- CSP 문자열, 스크립트 네 개와 순서, `file://` 실행, `fetch(` 두 번, `.setItem(` 두 번, 저장 키 두 개.
- 판정·점수·완료를 뜻하는 표현을 쓰지 않는다. 표시가 사라져도 검토 완료가 아니라는 안내는 그대로다.
- 엔진·규칙·데이터 파일은 바꾸지 않았다(규칙셋 `…-bb9129d56827`, 매칭 `match-2b470bfabfd83536` 그대로).
- 새 브라우저 API(`ResizeObserver`, `requestAnimationFrame`, `Blob`, `window.addEventListener`)는 존재를 확인한 뒤에만 쓴다. 테스트의 가짜 DOM에서도 앱이 부팅된다.
