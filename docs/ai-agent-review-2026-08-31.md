# Claude MCP × Codex 재감리 기록

검토일: 2026-08-31
대상: FairPost/FairMCP v0.3 후보의 제품 취지 강화

## 감리 방법

- Claude Code 2.1.251의 프로젝트 MCP 신뢰와 서버 승인을 실제 대화형 절차로 완료했다.
- 초기 감리에서는 `fairpost-local`이 루프백 `http://127.0.0.1:8000/mcp`에서 네 도구로 연결된 상태를 확인했다. 이후 기본 별칭을 `fairpost`로 바꾸고 구조화 점검을 추가해 전체 5도구로 확장했다.
- Claude Opus 4.8이 합성 공고를 대상으로 `check_job_posting`과
  `next_review_question`을 실제 호출했다. 호출은 권한 거부 없이 끝났고 파일은
  수정하지 않았다.
- Codex와 독립 에이전트가 제품 경계, 코드 흐름, 보안ㆍ프라이버시를 별도로
  읽고 Claude의 관찰과 대조했다.

이 감리는 모델의 의견만으로 규칙을 승격하지 않는다. 실제 코드, 도구 출력,
원문 offset 회귀, 공개ㆍ민간 train 익명 집계를 함께 확인하고 사람 검토가 필요한
성능 주장은 계속 보류한다.

## Claude MCP 실제 호출 관찰

합성 입력에는 연령 암시, 출생연도 제한, 성별 우대, 건강ㆍ외모 표현과 불완전한
절차ㆍ정보 안내를 함께 넣었다.

- 호출 도구: `check_job_posting`, `next_review_question`
- finding ID: 0개
- 직접 문맥 질문: `Q-DIST-015`의 `남성 우대`, `Q-PROC-006`의 `우대`
- 누락 안내에 연결된 질문: `Q-DIST-001`, `Q-DIST-002`, `Q-PROC-002`,
  `Q-PROC-003`, `Q-INFO-001`~`Q-INFO-005`

`남성 우대`를 곧바로 법 위반 finding으로 만들지 않고 직무 본질성 또는 적극적
고용개선 근거를 묻는 `Q-DIST-015`로 보낸 것은 기존의 사람 검토 정책과
일치했다. 반면 `젊고`, `1995년 이후 출생자만`, `외모 단정한`은 기존 법령
표현 규칙의 명백한 어순ㆍ활용 변형인데도 finding 근거가 남지 않았다.

이에 `AGE-001`, `AGE-002`, `LOOK-001`에 세 변형을 최소 범위로 추가하고,
각 매칭 문구가 입력 원문의 정확한 offset을 가리키는 회귀 테스트를 고정했다.
공공 210건ㆍ민간 2,100건 train 익명 집계에서는 세 추가 변형으로 새 관찰 건수가
생기지 않았다. 따라서 이 변경은 합성 경계 회귀 근거이며 사람 정밀도 또는 시장
빈도 증거로 해석하지 않는다.

## 독립 감리 합의와 구현 결정

| 감리 관찰 | 구현 결정 | 수용 기준 |
|---|---|---|
| 가장 짧은 MCP 이름이 원격을 가리켜 로컬 우선 원칙과 충돌 | `.mcp.json`의 `fairpost`를 루프백 기본으로, Vercel은 `fairpost-remote`로 분리 | 기본 이름만 사용하면 공고문이 기기 밖으로 나가지 않음 |
| 공개 MCP 설명이 로컬ㆍClaude 프로필보다 약함 | 공개 서버와 세 도구 설명에 근거 기반 사람 검토, 비판정, 비영속 경계를 명시 | 도구 목록만 읽어도 공정성ㆍ법률ㆍ합격 판정이 아님을 알 수 있음 |
| 한 질문씩 받으면 offsetㆍ문헌ㆍ버전 근거가 빠짐 | 질문 payload에 `offset`, `book_ref`, `reference`, 저장 답변 상태와 규칙ㆍ법령 버전을 추가 | 단일 질문 응답만으로 발동 이유와 근거 버전을 추적 가능 |
| 평문 점검 결과는 기계가 finding→질문→근거 연결을 안정적으로 재사용하기 어려움 | 기존 평문 계약은 유지하고 별도 `check_job_posting_structured` v1을 로컬ㆍ일반 원격 읽기 도구로 추가 | 스키마 버전, 원문 offset, 법령 근거, 연결 질문ㆍ문헌을 JSON Schema로 검증하며 원격 저장은 추가하지 않음 |
| MCP 텍스트가 건수ㆍ우선도부터 보여 판정처럼 읽힐 수 있음 | 고정 면책문을 첫 블록으로 이동하고 `심각도`를 `검토 우선도`로 표시 | 첫 화면에서 판정ㆍ법률 자문이 아님을 먼저 확인 |
| 웹 제목ㆍ버튼ㆍ개수 스트립이 체크 도구 인상을 줌 | `채용공고 검토 메모`, `검토 메모 만들기`, 사람 검토 작업량 문구로 통일 | 개수를 점수ㆍ등급ㆍ합격ㆍ공정성 판정으로 해석하지 않도록 실행 전후 고지 |
| 제목 없는 한 줄 공고의 슬롯 증거가 줄 전체를 반복 | 매칭 문장 우선, 긴 문장은 매칭을 포함한 제한 창만 반환하고 Pythonㆍ웹 패리티 고정 | 관련 문맥은 남기고 무관한 원문 반복은 줄임 |
| 웹이 분석ㆍ표시ㆍ복사로 끝나 담당자 결정이 결과와 분리됨 | 질문별 담당자 답변, 답변 진행률, 답변이 포함된 복사 메모를 추가하고 답변은 현재 분석 메모리에만 유지 | 근거ㆍ질문ㆍ사람 답변이 한 메모에 연결되고 재분석ㆍ입력 지우기 때 답변이 삭제됨 |

## 프로덕션 재검증과 런타임 보완

- 구조화 도구 추가 전 중간 Vercel 프로덕션 `dpl_3KBirjjcmhiSz4M3WVvGXjdUq9Af`를 배포하고 고정 별칭
  `https://fairmcp.vercel.app`에서 현재 규칙ㆍ매칭ㆍ런타임 지문을 대조했다.
- 배포 검증기는 익명 초기화가 `401`로 닫히는지, 인증 후 공개 읽기 전용 도구가
  정확히 2개인지, 두 도구를 모두 실제 호출할 수 있는지 확인했다. 검증에는 합성
  공고만 사용했고 토큰과 공고 원문은 감사 보고서에 기록하지 않았다.
- 첫 재검증에서 비ASCII 민감 토큰이 설정되면 문자열 상수시간 비교가 `500`을
  일으키는 서버리스 경계 결함을 함수 로그로 발견했다. 인증 헤더 원시 바이트와
  UTF-8 기대값을 비교하도록 수정하고 비ASCII 토큰 회귀를 추가했다.
- 공식 MCP Inspector 2.4.0으로 도구 목록과 `check_job_posting`을 다시 호출했다.
  두 도구의 비판정ㆍ비영속 설명과 읽기 전용 주석, 면책문 선행, `SEX-001`의
  법령 조문 연결을 현재 프로덕션에서 확인했다.

## 유지한 안전 경계

- 정적 웹의 `connect-src 'none'`과 로컬 실행 기본값
- 루프백 전체 MCP 5도구, 일반 원격 읽기 전용 3도구, Claude 호환 평문 1도구의 분리
- 공고문 원문 비영속, 원격 답변 저장 금지
- 규칙 ID, 원문 offset, 법령 조문ㆍ스냅샷, 질문 문헌 근거
- 성별 우대처럼 적용 맥락이 필요한 표현을 자동 위반 finding으로 승격하지 않는 정책
- 사람 라벨 없는 G1ㆍG2, v1.0 준비, 운영 SLA 주장 금지
