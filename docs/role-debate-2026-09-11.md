# FairPost 발전 방향 역할 토론 초안

작성일: 2026-09-11
범위: 저장소 현재 구현, 기존 검토 기록, 한국산업인력공단 NCS 공정채용 누리집

> 이 문서는 실시간 Claude 세션의 답변을 수신한 기록이 아니다. 현재 저장소와 공식 자료를 바탕으로 여러 역할의 관점과 합의안을 먼저 구조화한 회의 초안이다. 실제 Claude 또는 외부 참여자 의견은 별도 동의와 독립 세션으로 수신한 뒤 출처·시각과 함께 추가해야 한다.

## 공통 사실

한국산업인력공단의 공식 공정채용 프로세스는 `분석 → 설계 → 개발 → 운영 → 평가`의 5단계로 설명된다. 공정채용 소개는 출신·가족관계·학력·외모 등 편견 유발 요인을 제거하고 직무능력을 평가하는 방향을 제시한다. 따라서 FairPost의 다음 확장은 “문구를 더 많이 탐지”하는 것보다 5단계의 근거와 책임을 연결하는 쪽이 우선이다.

## 역할별 발언 요지

| 참여 역할 | 핵심 주장 | 바로 필요한 결과 |
|---|---|---|
| 위원장 (`chair`) | 자동 판정이 아니라 쟁점 조정과 미해결 이슈의 종료 조건이 제품의 중심이어야 한다. | `edit_requested`·`escalate`가 남으면 완료로 표시하지 않는 상태 규칙 |
| 인사 운영책임자 (`hr_owner`) | 탐지 결과가 실제 공고·지원서·면접 운영 수정으로 이어져야 한다. | 질문별 조치, 담당자, 기한, 완료 근거를 기록하는 후속 흐름 |
| 직무전문가 (`job_sme`) | 자격·필기·면접 요소는 NCS 능력단위/KSA 또는 실제 직무 수행과 연결돼야 한다. | 각 요건과 평가요소의 직무관련성 근거 링크 |
| 면접위원 (`interviewer`) | 블라인드 정보 차단과 사전 교육·이해충돌 확인 없이는 공정한 평가 설계가 운영에서 무너진다. | 면접위원용 정보 범위, 교육 확인, 평가기준 버전 기록 |
| 정책검토자 (`policy_reviewer`) | NCS 지침, 법령, 조직 내부정책을 같은 강도의 규칙처럼 섞으면 안 된다. | `guidance_not_law`, 법령 검증 결과, 예외 근거의 분리 표시 |
| 감사자 (`auditor`) | 현재 v1.0의 병목은 AI가 아니라 사람 라벨 holdout, 출처 다양성, 재현 가능한 릴리스 증거다. | G1/G2, 민간 출처 다양성, ruleset·catalog 버전, release artifact |
| 지원자 대변인 (`candidate_advocate`) | 불필요한 개인정보·증빙·절차 부담을 줄이고 지원자가 평가 기준을 이해할 수 있어야 한다. | 최소 수집, 단계별 증빙 시점, 평가요소 사전 공개 점검 |

## 합의안

1. **P0 — 신뢰성 게이트를 먼저 닫는다.** 사람 라벨 sealed holdout에서 precision/recall 목표를 확인하고, 단일 민간 출처 편중과 `coverage_gap`을 해결한다. 테스트 통과만으로 v1.0을 선언하지 않는다.
2. **P1 — 다중 역할 검토를 기록한다.** 역할마다 독립 이벤트를 남기고 위원장이 조정한다. 패킷에는 공고 원문 대신 fingerprint만 두며, 근거는 질문·규칙·출처 ID로 참조한다.
3. **P1 — NCS 단계와 제품 흐름을 연결한다.** 직무분석은 `analysis`, 평가기준과 공고 설계는 `design`, 질문·서식 개발은 `development`, 위원 교육과 실제 전형은 `implementation`, 사후 평가·환류는 `evaluation`에 기록한다.
4. **P2 — AI와 원격 공유는 opt-in으로 둔다.** AI는 설명·초안 보조에 한정하고 자동 합격/불합격이나 차별 확정 판정을 하지 않는다. 원격 공유는 인증·조직 권한·보존·삭제·암호화 정책을 먼저 확정한다.

## 이견과 결정 보류

- 2026년 가이드북은 공식 자료실 게시 항목을 확인했지만, 현재 카탈로그는 첨부 원문을 조항별로 대조한 상태가 아니다. 따라서 게시 사실은 최신성 신호로만 쓰고, 세부 통제의 근거로 확대 해석하지 않는다.
- 민간기업에 공공기관 모니터링 사례를 동일한 법적 의무로 적용하지 않는다.
- 키워드 일치 결과만으로 차별 또는 위법을 확정하지 않는다. 직무관련성, 예외 근거, 실제 운영 증거와 사람 검토가 필요하다.

## 구현 연결

현재 초안의 데이터 계약은 [다중 역할 검토 패킷](./review-packet.md)에 있다. `ReviewEvent`는 역할·NCS 단계·행동·근거 참조·버전·시각을 기록하고, `ReviewPacket`은 `posting_fingerprint`만 저장한다. 엔진·로컬 저장소·브라우저 역할 검토 큐 연결은 구현됐으며, 다음 작업은 `edit_requested`·`escalate`를 이슈별로 종료하는 상태와 실제 파일럿 피드백에 연결하는 것이다.
