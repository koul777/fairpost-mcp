# 책 부록 프로그램 설계 검토 · 2026-10-09

대상: FairPost 채용공고 검토 프로그램과 「본문_AI시대 공정이란 무엇인가_1006_교정메모.pdf」.
상태: 책 근거 및 설계 경계 검토 완료. 이 문서는 구현·브라우저 검증의 완료 보고가 아니며, 실제 동작의 수용 확인은 통합 검증에서 기록한다.

책의 부록 소개는 채용공고에서 관련 법규·공정성의 검토 지점을 찾고 조직에 질문을 건네는 도구를 설명한다(인쇄 302~303쪽, PDF 155). 프로그램의 기본 흐름은 **공고 입력 → 표현·안내·네 관점 질문 검토 → 근거와 후속 조치 기록 → 수정 후 재검토**로 둔다. 공정성의 점수·등급·최종 판정은 만들지 않는다.

## 1. 근거의 범위

10월 교정본은 펼침면 163 PDF 페이지다. 인쇄 쪽수와 PDF의 1기반 파일 페이지를 구분하며, 장절과 질문 ID의 구체적 연결은 [책과 저장소 매핑](book-map.md)을 따른다.

| 근거 위치 | 설계에 반영할 내용 | 해석의 경계 |
|---|---|---|
| 들어가며 2~7쪽 · PDF 5~7 | 네 관점을 기본 흐름에서 이해하고 질문할 수 있게 한다. | 네 관점을 점수로 합산하거나 질문 수를 공정성 정도로 해석하지 않는다. |
| 들어가며 10~13쪽 · PDF 9~10 | 기준·설명·문의·재검토를 사전에 준비하도록 돕는다. | 공고에 문구를 추가했다는 사실만으로 운영 체계가 마련됐다고 판단하지 않는다. |
| 2부 2-2, 126쪽 · PDF 67 | AI 평가 설명·피드백·인간 재검토·책임을 묻는다. | AI를 쓴다는 공고 표현과 실제 자동화 범위·담당자의 권한은 다른 사실이다. |
| 3부 3-3, 202~203쪽 · PDF 105 | 지원자 의견·소명·인간 접점·분석 범위 고지를 묻는다. | 텍스트의 정중함이 실제 존중 경험을 증명하지 않는다. |
| 4부 4-2, 262쪽 · PDF 135; 4-3, 270쪽 · PDF 139 | 자료의 적합성·대리변수·외부 검증·재검토의 운영 질문을 연결한다. | 프로그램이 모델·데이터 감사나 집단별 선발 결과 분석을 수행하는 것은 아니다. |
| 마무리하며 298~299쪽 · PDF 153 | 검토자의 권한·시간·정보·책임과 근거를 남긴다. | 답변 완료, 역할별 승인, 체크박스는 공정성 인증이 아니다. |
| 마무리하며 302~303쪽 · PDF 155 | 채용공고를 작은 실천의 출발점으로 삼는다. | 성과평가·보상·승진까지 분석 대상을 넓히지 않는다. |

페이지 경계에 주의한다. PDF 67에는 다음 장 2-3의 표제가 함께 추출되지만 126쪽 체크리스트는 2-2에 속한다. PDF 135의 262쪽 체크리스트는 4-2, PDF 139의 270쪽 체크리스트는 4-3에 속한다. 현재 표의 일부 장 시작 쪽수는 목차(PDF 3~4)와 해당 펼침면을 함께 대조했다.

## 2. 네 관점의 기본 안내

아래는 책을 채용공고에 적용한 제품용 요약이다. 원문 인용이나 법적 기준 목록이 아니다.

| 관점 | 사용자에게 보여 줄 짧은 안내 |
|---|---|
| 분배 · 기회와 요건 | 지원 기회와 자격·우대 요건이 직무에 맞는지 살펴봅니다. |
| 절차 · 기준과 재검토 | 기준과 진행 절차가 설명되고, 이의를 말할 통로가 있는지 살펴봅니다. |
| 대인 · 존중과 목소리 | 지원자를 존중하는 표현과 사람에게 이야기할 통로를 살펴봅니다. |
| 정보 · 설명과 접근 | 지원자가 필요한 정보와 이유를 이해하고 물을 수 있는지 살펴봅니다. |

관점은 서로 겹칠 수 있다. 문의 창구는 절차·대인·정보에 모두 연결될 수 있으므로 배타적인 점수 구역으로 만들지 않는다. 구현은 기존 질문 ID·관점·발동 조건을 재사용한다. 새로운 질문 생성이나 네 관점별 최소 질문 수를 맞추기 위해 엔진 규칙을 바꾸지 않는다.

기본 화면에서 관련 질문을 읽고 답할 수 있어야 한다. 전문가 모드는 상세 근거를 더 살피는 경로이며, 사람의 검토 자체를 전문가 모드에만 가두지 않는다. 관련 표현이 없을 때도 현재 엔진이 반환한 운영 질문은 남을 수 있다. 질문이 없거나 표시된 표현이 0개인 상태는 통과 판정이 아니다.

## 3. 관찰과 운영 사실을 구분한다

| 구분 | 프로그램이 제시할 수 있는 것 | 담당자가 별도로 확인할 것 |
|---|---|---|
| 표현 | 해당 규칙이 포착한 원문 위치, 연결된 근거와 대안 | 해당 직무의 실제 필요성, 예외의 적용 사실, 수정 여부와 이유 |
| 안내 | 입력 공고에서 탐지되거나 탐지되지 않은 안내 항목 | 다른 안내문·채용 시스템의 내용, 최신 일정, 실제 문의처 운영 여부 |
| 운영 질문 | 공고의 맥락에 맞는 질문과 후속 질문 | 기준 적용 이력, 인간의 개입 권한, 실제 소명 처리와 피드백 |
| AI·데이터 관련 질문 | 사용 범위·자료 검증·책임을 확인할 질문 | 학습·검증 데이터, 계약·감사자료, 분석 범위, 편향 검증 결과 |

권장 공통 문구: “공고에 적힌 내용과 담당자가 확인할 운영 질문을 함께 살펴봅니다. 공고에서 확인되지 않는다고 실제 제도가 없다는 뜻은 아닙니다.”

AI 언급이 없더라도 실제 사용 여부는 담당자가 확인할 수 있다. 그렇다고 시스템이 AI 사용을 추정해 확정하거나 모든 AI 질문을 무조건 발동시키지는 않는다. 담당자가 아직 확인하지 못한 사실은 미확인으로 남기며, 답변을 근거로 자동 적법·공정 판정을 만들지 않는다.

## 4. 기록과 재검토

기록에는 확인한 사실과 자료, 수정 이유, 남은 확인사항, 담당자와 다음 행동을 남길 수 있게 한다. 담당자 이름이나 완료 표시는 책임의 소재를 설명하는 기록일 뿐, 감사 결과나 승인 인증이 아니다.

모드가 달라도 같은 질문 ID는 같은 답변을 사용해야 한다. 동일 ID의 답변 입력창 중복, 전환 과정의 답변 소실, 이전 공고의 답변을 새 공고의 확인 결과로 오인하는 상황을 막는다. 공고 변경 후에는 재검토 전 결과·메모가 현재 입력을 반영하지 않는다는 상태를 드러내고 최신 결과인 것처럼 복사되지 않게 한다.

질문 답변과 역할 기록의 보관 방식은 실제 구현에 맞게 안내한다. 메모리·브라우저 저장소·복사한 파일을 모두 영구 저장처럼 설명하지 않는다. 새로고침, 저장 불가, 재검토 때의 유지·초기화 정책을 검증한 뒤 독자 안내에 적는다. 공고문과 답변을 자동 외부 전송하지 않는다.

## 5. 책 연결과 법령·연구 근거 표시

책 연결은 질문을 이해하는 독서 경로다. 법령·연구·가이드의 직접 근거는 별도로 자료명과 위치를 표시한다. 현재 `book_ref`에는 책 장절과 외부 보고서의 장·쪽수가 혼재하므로 모든 값을 “이 책의 근거”로 묶지 않는다.

예를 들어 `Q-PROC-004`의 제6장 270~272쪽은 외부 AI 채용 연구보고서 위치이며, 이 책의 연결 위치인 인쇄 126쪽/PDF 67과 다르다. `Q-INFO-009`의 제5장 211~218쪽 역시 별도 가이드라인 연구의 위치다. `Q-INFO-010`의 PDF 14쪽은 외부 NCS 연결로, 이 교정본의 PDF 14가 아니다. 원자료의 파일 쪽수와 인쇄 쪽수 대조는 기존 [외부 가이드 맵](ability-based-hiring-guide-map.md)의 확인 범위를 따른다.

이번 작업은 외부 연구의 원문 정확도나 법령의 현행성·개별 적용 여부를 재검증하지 않았다. 이 문서의 날짜는 책 매핑의 검토일이며, 규칙의 `provenance.reviewed_at`이나 법령 스냅샷 날짜를 대체하지 않는다. `consensus` 운영 질문을 법률 의무로, 외부 가이드 질문을 위반 탐지로 승격하지 않는다.

## 6. 로컬 프로그램과 선택 연동

독자는 로컬 검토 화면에서 공고를 입력하고 질문에 답할 수 있어야 한다. MCP 클라이언트나 외부 AI 키를 기본 사용의 전제조건으로 요구하지 않는다. 결정론적 기본 엔진과 외부 AI 없는 기본 분석을 유지하며, 선택 AI 연동은 사용자가 전송 범위와 실행 의도를 확인하는 별도 흐름에 둔다.

로컬 실행 방식과 책의 연결은 제품 설계 결정이다. 책의 “MCP”라는 명칭을 근거로 모든 독자에게 MCP 구성을 요구하지 않는다. 원고의 명칭을 “채용공고 검토 프로그램(FairPost, MCP 선택 연동 지원)” 등으로 안내하는 것은 편집 제안으로만 전달하며 원고 자체를 수정하지 않는다.

인쇄 302쪽/PDF 155에는 QR 접속 오류의 교정 메모가 있다. 이번 문서 작업에서는 QR 목적지를 추출하거나 실제 접속을 검증하지 않았다. 인쇄 전 확정한 독자용 주소·QR과 로컬 실행 안내의 일치는 별도 확인 항목이다.

## 7. 통합 검증에서 확인할 수용 기준

| 사용자 흐름 | 수용 증거 |
|---|---|
| 일반 채용·AI 채용 예시 검토 | 기본 화면에서 네 관점의 의미와 엔진이 반환한 관련 질문에 접근할 수 있다. |
| 질문 답변 후 모드 왕복 | 같은 질문의 답변이 유지되며 DOM ID가 중복되지 않는다. |
| 표현이 0개인 결과 | 통과·공정 인증으로 표현하지 않고 남아 있는 운영 질문을 확인할 수 있다. |
| 근거·수정 이유·다음 행동 기록 | 기록 위치와 실제 보관 범위가 일치하며 저장 실패를 숨기지 않는다. |
| 공고 수정 후 재검토 | 오래된 결과의 복사가 차단되고 새 결과와 이전 기록의 관계가 드러난다. |
| 출처 확인 | 책 연결과 외부 법령·연구·가이드의 제목·위치를 혼동하지 않는다. |
| 로컬 첫 실행 | MCP·외부 AI 키 없이 기본 검토를 시작하고 기본 엔진은 외부 AI를 호출하지 않는다. |
| 모바일·키보드 사용 | 긴 한국어 안내와 질문·입력창을 읽고 조작할 수 있다. |

이 표는 수용 기준이며 실행 결과가 아니다. UI·로컬 실행 담당자의 테스트와 코디네이터의 실제 브라우저 검증으로 충족 여부를 기록한다. 본 작업의 산출물은 문서 2개와 로컬 결정·보고 파일이며 코드·규칙 변경은 포함하지 않는다.
