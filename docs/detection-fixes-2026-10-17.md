## RT-1 — 공백 수량자 역추적 병목

실제 공고에 긴 공백이 섞이면 한 건 검사에 2초 넘게 걸렸다. 선택 토큰을 사이에 둔 두 공백 수량자
(`\s*(?:을|를)?\s*`, `[ \t]*[:：-]?[ \t]*`)는 하나의 공백 구간을 나누는 모든 방법을 시도하고,
선택 공백으로 시작하는 패턴(`(?:별도|개별)?[ \t]*…`)은 공백 구간의 모든 위치에서 탐색을 다시 시작한다.

엔진 안에서 실제 병목이었던 입력(공백ㆍ탭 2만 자, Python 프로세스 CPU 시간):

| 입력 | 관련 규칙 | 수정 전 | 수정 후 |
|---|---|---|---|
| 불합격자 미통보 문장 뒤 `결과 안내` + 공백 | Q-INFO-014 | 4.4초 | 0.03초 |
| `탈락 시 연락 없음` + 탭 | Q-INFO-014 | 5.3초 | 0.01초 |
| `남성 직원` + 공백 | SEX-001 | 5.4초 | 0.01초 |
| `여성` + 공백 | Q-DIST-015 | 5.1초 | 0.02초 |

`최종학력`ㆍ`학력사항`ㆍ`전공명` 패턴은 정규식만 따로 돌리면 20초 넘게 걸리지만, 엔진은 질문 트리거 주변
600자 창 안에서만 실행하므로 엔진 단위 병목은 아니었다. 같은 형태이므로 함께 고쳤다.

- 공백 수량자 사이 선택 토큰 16개 패턴(선택 토큰이 둘인 `\s*(?:직원|…)?(?:을|를)?\s*` 포함)을 같은 문자열을
  받는 `WS (?:X WS)?` 형태로 바꿨고, 선택 공백 시작 1개 패턴은 `(?:(?:별도|개별)[ \t]*|(?<![ \t])[ \t]*)`로
  바꿨다. 공백 구간은 첫 글자에서만 시작하므로 가장 왼쪽 일치와 그 범위가 같다. 모두 17개.
- 패턴마다 해당 패턴의 낱말ㆍ기호ㆍ공백으로 만든 무작위 입력 6,000~20,000건에서 수정 전후 일치 위치와
  문자열이 같았다. 독립 검토에서 Python(IGNORECASE)과 웹 엔진의 정규식 변환(`giu`) 양쪽으로 약 120만 건을
  다시 비교해 불일치 0건이었고, 사전 검사 조건(필수 문자열 묶음)도 바뀌지 않았다.

회귀 테스트(`tests/test_detection_fixes_2026_10_17.py`): `data/` 아래 모든 YAML 정규식에 공백 수량자 사이
선택ㆍ반복 토큰, 선택 공백 시작, 빈 대안(`(?:가|나|)`)이 없는지 검사하고, 위 네 입력을 5초 프로세스 상한
안에 처리하는지 확인한다. 수정 전 엔진에서는 이 세 검사가 모두 실패한다. `tests/js_regex_conditions.cjs`는
바뀐 결과 미통보 패턴을 찾도록 갱신했다.

## RT-2 — 실제 공고의 오탐 4건

| 공고 문장(요지) | 수정 전 | 수정 후 | 근거 |
|---|---|---|---|
| 수정 공고의 `응시자격 중 연령제한 삭제` | AGE-002 | 표시 안 함 | 제한을 없앴다는 안내 |
| `고령자ㆍ준고령자 우대` 아래의 `고령자(55세 이상)`, `준고령자(50세 이상)` | AGE-002 | 표시 안 함 | 고령자고용법 제2조가 정한 범주, 우대는 제4조의5 4호 |
| `학력, 부모직업, 가족관계 등을 기재해 제출하면 감점` | FAMILY-001 | 표시 안 함 | 기재하면 불이익인 블라인드 안내 |
| 제출서류 `주민등록초본(남성만)` | SEX-001 | 표시 안 함 | 병역사항 확인 서류 안내 |

모든 제외는 해당 규칙에만 두고, 후보와 겹치는 문맥에만 적용한다(`overlap_candidate`).

- AGE-002, 연령제한 삭제: `(연령|나이) 제한 (삭제|폐지|철폐|해제)`. `삭제 예정ㆍ검토ㆍ불가ㆍ계획`, `삭제는 하지
  않습니다`, `삭제 안 함`처럼 계획이거나 부정한 경우는 제외하지 않는다.
- AGE-002, 고령자ㆍ준고령자: 괄호로 정의한 범주(`(준)고령자(50ㆍ55세 …)`)에 우대ㆍ가점ㆍ가산ㆍ우선이 함께
  있을 때만 제외한다. 범주 앞의 우대 표시(80자 안, 제외ㆍ불가ㆍ제한ㆍ없음 같은 거부 표현이 끼지 않을 때)이거나
  범주(또는 `및`ㆍ`,`로 나열한 범주) 바로 뒤의 우대 표시다. 범주 뒤 40자 안에 거부ㆍ한정 표현이 있으면
  제외하지 않는다. `고령자(55세 이상)는 응시할 수 없습니다`, `지원 제외 대상: 준고령자(…)`,
  `준고령자(…)만 지원 가능`, 괄호 없는 `만 55세 이상인 자`는 그대로 표시한다.
- FAMILY-001: 항목 바로 뒤에 항목 나열ㆍ`등`ㆍ조사만 오고 `기재ㆍ기입ㆍ표기`(`하여/해서/해`, `제출/지원`)한
  `시ㆍ경우ㆍ때`나 `하면ㆍ되면` 뒤 12자 안에 `감점ㆍ불이익ㆍ불합격ㆍ실격`이 올 때만 제외한다. `허위로 기재`,
  `입력하지 않으면`, `미기재`, `불이익이 없도록`, 다른 항목에 붙은 감점(`출신학교 기재 시 감점, 부모 직업은
  반드시 기재`)은 그대로 표시한다. 엔진 공통 보호 표현 목록은 바꾸지 않았다.
- SEX-001: `초본ㆍ병역(사항)ㆍ병적(증명서ㆍ기록)` 바로 뒤의 `남성만`ㆍ`남성에 한` 이 서류 문맥(닫는 괄호, 병역ㆍ
  제출ㆍ기재ㆍ발급이 이어지는 괄호나 쉼표, `해당ㆍ제출ㆍ기재ㆍ발급`)으로 이어질 때만 제외한다.
  `병역: 남성만 지원 가능`, `병역사항(남성만 지원 가능)`, `주민등록초본: 남성만 응시 가능`,
  `병역필 남성만 지원 가능`은 그대로 표시한다.

회귀 테스트: 고친 문장 12개, 그대로 표시해야 할 실제 제한 27개(독립 검토가 첫 초안에서 찾아낸 누락 형태
16개 포함), 모든 사례의 CRLFㆍ공고 안 변형까지 Pythonㆍ웹 일치.

## 독립 검토

작업에 참여하지 않은 별도 에이전트가 첫 초안을 검토해 차단급 3건을 찾았다. 엔진 공통 보호 표현에
`기재 시 감점`을 더한 초안은 `허위로 기재`, `입력하지 않으면`, 서식 문구(`작성 시 허위 기재 … 불합격`)까지
보호로 읽어 FAMILY-001ㆍBODY-001ㆍPHOTO-001ㆍSEX-002ㆍPREG-001의 실제 요구를 숨겼다. 고령자 제외는 거부
표현 목록 방식이라 `응시할 수 없습니다` 같은 거부를 숨겼고, 병역 제외는 `병역: 남성만 지원 가능`을 숨겼다.
위처럼 공통 보호 표현 추가를 되돌리고, 세 제외를 규칙별ㆍ문맥 한정으로 바꿨다. 검토자의 공격 사례 155건과
변형 236건을 다시 돌려 바뀐 결과가 의도한 수정 사례뿐이고 Pythonㆍ웹 불일치가 0건임을 확인했다.

## 증거 재생성 (코퍼스가 있는 PC)

규칙셋ㆍ매칭 버전이 바뀌어 코퍼스 기반 보고서를 다시 만들어야 한다. 클라우드 작업 환경에는 비공개
코퍼스가 없어 아래는 PC에서 같은 브랜치에 이어서 한다. 2026-10-10 재생성 커밋(`90243da`)과 같은 절차다.

1. `python tools/refresh_evidence.py --all`
2. `private_fairness_audit.json`, `private_open_training_analysis.json`, `private_review_sampling_audit.json`을
   `docs/private-fairness-monitoring.md`의 절차로 같은 스냅샷에서 다시 만든다.
3. `python tools/validate_data.py`가 `provenance.corpus_hits` 불일치를 알리면 `data/rules/law.yaml`의 해당
   규칙 값을 새 집계로 고친다(AGE-002ㆍSEX-001ㆍFAMILY-001이 후보). 질문 집계가 바뀌면
   `question_relevance_manual_review`의 재집계 기록도 갱신한다.
4. 배포본 감사와 증거 버전 감사를 마지막에 다시 만들고 전체 테스트를 돌린다.

과거 집계 보고서 15개는 수치와 원래 버전을 보존하고 `current_ruleset_version`ㆍ`current_matching_version`만
새 엔진으로 갱신했다. `examples/pilot_feedback.example.jsonl`은 합성 예제이므로 버전만 바꿨다.
