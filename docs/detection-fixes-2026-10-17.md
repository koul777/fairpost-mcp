## RT-1 — 공백 수량자 역추적 병목

실제 공고에 긴 공백이 섞이면 한 건 검사에 2초 넘게 걸렸고, 그 99%가 결과 미통보 탈락 질문의 정규식
하나였다. `(?:별도|개별)?[ \t]*`로 시작해 공백 구간의 모든 위치에서 다시 탐색을 시작했다.

규칙 정규식 전수 점검에서 같은 계열이 더 나왔다. 선택 토큰을 사이에 둔 두 공백 수량자
(`\s*(?:을|를)?\s*`, `[ \t]*[:：-]?[ \t]*`)는 하나의 공백 구간을 나누는 모든 방법을 시도한다.
`최종학력`ㆍ`학력사항`ㆍ`전공명` 뒤에 공백 2만 자가 오면 한 번에 20초 넘게, `여성`ㆍ`남성` 뒤면
5~10초가 걸렸다. 공개 서버 함수 제한(60초)을 위협하는 입력이다.

- `WS X? WS`를 같은 문자열을 받는 `WS (?:X WS)?`로 바꿨다(17개 패턴). 선택 토큰이 둘인
  `\s*(?:직원|…)?(?:을|를)?\s*`은 `\s*(?:(?:(?:직원|…)(?:을|를)?|(?:을|를))\s*)?`로 바꿨다.
- 결과 미통보 패턴의 앞부분은 `(?:(?:별도|개별)[ \t]*|(?<![ \t])[ \t]*)`로 바꿨다. 공백 구간은 첫 글자에서만
  시작하므로 가장 왼쪽 일치와 그 범위가 같다.
- 패턴마다 해당 패턴의 낱말ㆍ기호ㆍ공백으로 만든 무작위 입력 6,000건(두 선택 토큰 패턴은 20,000건)에서
  수정 전후 일치 위치와 문자열이 모두 같았다. 사전 검사 조건(필수 문자열 묶음)도 바뀌지 않았다.
- 최악 사례: 22.9초 → 0.004초 수준.

회귀 테스트: `tests/test_detection_fixes_2026_10_17.py`의 구조 검사(규칙 정규식에 `WS X? WS`나 선택 공백
시작이 없어야 함)와 긴 공백 6종의 처리 시간 상한(프로세스 단위 20초), `tests/js_regex_conditions.cjs`의
대상 패턴 갱신.

## RT-2 — 실제 공고의 오탐 4건

| 공고 문장(요지) | 수정 전 | 수정 후 | 근거 |
|---|---|---|---|
| 수정 공고의 `응시자격 중 연령제한 삭제` | AGE-002 | 표시 안 함 | 제한을 없앴다는 안내 |
| `고령자(55세 이상)`, `준고령자(50세 이상)` 우대 | AGE-002 | 표시 안 함 | 고령자고용법 제2조가 정한 범주, 우대는 제4조의5 4호 |
| `학력, 부모직업, 가족관계 등을 기재해 제출하면 감점` | FAMILY-001 | 표시 안 함 | 기재하면 불이익인 블라인드 안내 |
| 제출서류 `주민등록초본(남성만)` | SEX-001 | 표시 안 함 | 병역사항 확인 서류 안내 |

- AGE-002 제외: `(연령|나이) 제한 (삭제|폐지|철폐|해제)`. `삭제 예정`, `삭제하지 않` 은 제외하지 않는다.
- AGE-002 제외: `(준)고령자(50ㆍ55세 …)` 괄호 정의와 겹친 후보만. 같은 줄 20자 안에 `제외ㆍ불가ㆍ제한ㆍ배제ㆍ
  지원할 수 없`이 오면 제외하지 않는다. 괄호 없는 `만 55세 이상인 자`는 그대로 표시한다.
- 보호 표현(Pythonㆍ웹 같은 목록): 항목을 `기재ㆍ작성ㆍ기입ㆍ표기`(`하여/해서/해`, `제출/지원`)한 `시ㆍ경우ㆍ때`,
  `하면ㆍ되면` 뒤 24자 안의 `감점ㆍ불이익ㆍ불합격ㆍ실격`. `미기재`, `허위 기재`, `잘못 기재`, `다르게 기재`와
  불이익을 부정한 문장(`기재 시 불이익 없음`)은 보호로 읽지 않는다. 누락 불이익(`기재하지 않으면 감점`)은
  기존대로 먼저 요구로 판정한다.
- SEX-001 제외: `초본ㆍ병역(사항)ㆍ병적(증명서ㆍ기록)` 바로 뒤의 `(남성만…)`, `남성에 한` 과 겹친 후보만.
  `병역필 남성만 지원 가능`, `남성만 지원 가능하며 주민등록초본 제출`은 그대로 표시한다.

회귀 테스트: `tests/test_detection_fixes_2026_10_17.py`(고친 문장 11개, 유지해야 할 실제 제한 11개,
모든 사례의 CRLFㆍ공고 안 변형까지 Pythonㆍ웹 일치).

## 증거 재생성 (코퍼스가 있는 PC)

규칙셋ㆍ매칭 버전이 바뀌어 코퍼스 기반 보고서를 다시 만들어야 한다. 클라우드 작업 환경에는 비공개
코퍼스가 없어 아래는 PC에서 같은 브랜치에 이어서 한다.

1. `python tools/refresh_evidence.py --all`
2. `private_fairness_audit.json`, `private_open_training_analysis.json`, `private_review_sampling_audit.json`을
   2026-10-10 기록과 같은 절차로 다시 만든다.
3. `python tools/validate_data.py`가 `provenance.corpus_hits` 불일치를 알리면 `data/rules/law.yaml`의 해당
   규칙 값을 새 집계로 고친다(AGE-002ㆍSEX-001ㆍFAMILY-001이 후보).
4. 배포본 감사와 증거 버전 감사를 마지막에 다시 만들고 전체 테스트를 돌린다.

과거 집계 보고서 15개는 수치와 원래 버전을 보존하고 `current_ruleset_version`ㆍ`current_matching_version`만
새 엔진으로 갱신했다. `examples/pilot_feedback.example.jsonl`은 합성 예제이므로 버전만 바꿨다.
