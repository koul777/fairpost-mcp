## RT-1 — 공백 수량자 역추적 병목

실제 공고에 긴 공백이 섞이면 한 건 검사에 2초 넘게 걸렸다. 선택 토큰을 사이에 둔 두 공백 수량자
(`\s*(?:을|를)?\s*`, `[ \t]*[:：-]?[ \t]*`)는 하나의 공백 구간을 나누는 모든 방법을 시도하고,
선택 공백으로 시작하는 패턴(`(?:별도|개별)?[ \t]*…`)은 공백 구간의 모든 위치에서 탐색을 다시 시작한다.

엔진 안에서 실제 병목이었던 입력(공백ㆍ탭 2만 자, Python 프로세스 CPU 시간):

| 입력 | 관련 규칙 | 수정 전 | 수정 후 |
|---|---|---|---|
| 불합격자 미통보 문장 뒤 `결과 안내` + 공백 | Q-INFO-014 | 4.4초 | 0.03초 |
| `탈락 시 연락 없음` + 탭 | Q-INFO-014 | 5.3초 | 0.01초 |
| `남성 직원` + 공백 | SEX-001 | 5.4초 | 0.01초 |
| `여성` + 공백 | Q-DIST-015 | 5.1초 | 0.02초 |

`최종학력`ㆍ`학력사항`ㆍ`전공명` 패턴은 정규식만 따로 돌리면 20초 넘게 걸리지만, 엔진은 질문 트리거 주변
600자 창 안에서만 실행하므로 엔진 단위 병목은 아니었다. 같은 형태이므로 함께 고쳤다.

- 공백 수량자 사이 선택 토큰 16개 패턴(선택 토큰이 둘인 `\s*(?:직원|…)?(?:을|를)?\s*` 포함)을 같은 문자열을
  받는 `WS (?:X WS)?` 형태로 바꿨고, 선택 공백 시작 1개 패턴은 `(?:(?:별도|개별)[ \t]*|(?<![ \t])[ \t]*)`로
  바꿨다. 공백 구간은 첫 글자에서만 시작하므로 가장 왼쪽 일치와 그 범위가 같다. 모두 17개.
- 패턴마다 해당 패턴의 낱말ㆍ기호ㆍ공백으로 만든 무작위 입력 6,000~20,000건에서 수정 전후 일치 위치와
  문자열이 같았다. 독립 검토에서 Python(IGNORECASE)과 웹 엔진의 정규식 변환(`giu`) 양쪽으로 약 120만 건을
  다시 비교해 불일치 0건이었고, 사전 검사 조건(필수 문자열 묶음)도 바뀌지 않았다.

회귀 테스트(`tests/test_detection_fixes_2026_10_17.py`): `data/` 아래 모든 YAML 정규식에 공백 수량자 사이
선택ㆍ반복 토큰, 선택 공백 시작, 빈 대안(`(?:가|나|)`)이 없는지 검사하고, 위 네 입력과 검토에서 찾은 역추적
공격 입력 2종을 5초 프로세스 상한 안에 처리하는지 확인한다. 수정 전 엔진에서는 공백 수량자 검사(16개 위반),
선택 공백 시작 검사(1개 위반), 시간 상한(약 20초)이 실패한다. 빈 대안은 수정 전에도 없었고 재발 방지용이다.
`tests/js_regex_conditions.cjs`는 바뀐 결과 미통보 패턴을 찾도록 갱신했다.

  있으면 제외하지 않는다.
- AGE-002, 고령자ㆍ준고령자: 괄호로 정의한 범주(`(준)고령자(50ㆍ55세 …)`)에 범주를 직접 가리키는 우대가 있고,
  그 줄이 범주나 우대 표시만으로 끝날 때만 제외한다.
  - 범주 앞: `고령자 및 준고령자(, 다른 항목) 등 우대`처럼 고령자를 이름으로 든 우대 표시가 줄을 넘는 80자

## 독립 검토

작업에 참여하지 않은 별도 에이전트가 네 차례 검토했다. 1~3차는 매번 차단급 문제가 나와 고쳤고, 4차에서는 차단급 문제가 없었다.

- 1차: 엔진 공통 보호 표현에 `기재 시 감점`을 더한 초안이 `허위로 기재`, `입력하지 않으면`, 서식 문구까지 보호로
  읽어 FAMILY-001ㆍBODY-001ㆍPHOTO-001ㆍSEX-002ㆍPREG-001의 실제 요구를 숨겼다. 고령자 제외는 거부 표현 목록
  방식이라 `응시할 수 없습니다`를 숨겼고, 병역 제외는 `병역: 남성만 지원 가능`을 숨겼다. 공통 보호 표현 추가를
  되돌리고 규칙별 제외로 바꿨다.
- 2차: FAMILY-001 제외의 항목 나열이 한 덩어리 한글을 여러 방식으로 나눠 6KB 입력에 Python 55초가 걸렸다.
  `경력 허위 기재` 같은 허위 기재가 나열 항목으로 읽혔고, `장애인 우대`처럼 다른 항목의 우대가 고령자 범주
  제외로 이어졌다. 세 제외를 허용 형태만 적는 방식으로 다시 썼다.
- 3차: 고령자 우대 나열 항목에 `와ㆍ과`가 들어가 지수적 역추적이 생겼다(226자에 Python 62초, 웹 35초).
  금지어 목록에 없는 허위 표현(`과장`, `날조`)은 여전히 나열 항목으로 읽혔고, 병역 제외의 여성 거부 확인이 좁았다.
  나열 항목에서 구분 음절을 빼고, 나열 뒤 `등`ㆍ조사를 필수로 하고, 고령자 범주 줄과 우대 표시의 끝을 고정했다.
  두 공격 입력은 이제 Pythonㆍ웹 모두 0.05초 이하이며 시간 상한 테스트에 넣었다.

정규식 재작성 17개는 1차에서 Python(IGNORECASE)과 웹 엔진 변환(`giu`) 양쪽으로 약 120만 건을 비교해 불일치
0건이었다. 검토자가 만든 공격 사례 373건과 변형 236건을 최종 규칙으로 다시 돌려, 바뀐 결과가 의도한 수정
사례뿐이고 Pythonㆍ웹 불일치가 0건임을 확인했다.

- 4차: 새 제외 패턴의 역추적은 Pythonㆍ웹 모두 사실상 선형이었다(제외 판정은 후보 주변 창 안에서만 돌아
  100KB 입력도 약 0.2초). 의도한 수정 외에 사라지는 실제 제한은 없었고, 아래 '남은 한계'의 드문 형태만 남았다.

- FAMILY-001: 허위 낱말 목록에 없는 표현이 `등`ㆍ조사로 끝나는 나열 안에 있을 때(`부모 직업, 경력 과장 등을 기재하면
  불이익`, `…날조 등을 기재 시 실격`).
- AGE-002 고령자 범주: 다음 줄의 조건(`※ 단, 고령자는 체력시험 통과자에 한함`), `고령자 우대 미시행` 같은 부정.
- SEX-001 병역 서류: 빈 줄 너머의 여성 거부(`병역(남성만 해당)\n\n여성 지원 불가`), 다른 줄의 성별 제한
  (`성별 제한: 남성`, `모집인원: 남성 2명`). 다른 줄의 `남성만 지원 가능`처럼 SEX-001이 따로 걸리는 표현은 그대로 표시된다.
- 연령제한 삭제: `연령 제한 해제 기준: 만 39세`(같은 줄의 연령 숫자는 따로 표시된다).

## 이번에 고치지 않은 것

청년 체험형 인턴의 `15세 이상 34세 이하`, `「청년기본법」상 청년(19세 이상~34세 이하)`처럼 법령상 예외일 수
있는 연령 요건은 법령명이 같은 줄에 없으면 AGE-002 `high`로 표시된다. 표시 수준은 법적 판단이 필요해
별도 결정으로 남긴다.

## 증거 재생성 (코퍼스가 있는 PC)

규칙셋ㆍ매칭 버전이 바뀌어 코퍼스 기반 보고서를 다시 만들어야 한다. 클라우드 작업 환경에는 비공개
코퍼스가 없어 아래는 PC에서 같은 브랜치에 이어서 한다. 2026-10-10 재생성 커밋(`90243da`)과 같은 절차다.

1. `python tools/refresh_evidence.py --all`
2. `private_fairness_audit.json`, `private_open_training_analysis.json`, `private_review_sampling_audit.json`을
   `docs/private-fairness-monitoring.md`의 절차로 같은 스냅샷에서 다시 만든다.
3. `python tools/validate_data.py`가 `provenance.corpus_hits` 불일치를 알리면 `data/rules/law.yaml`의 해당
   규칙 값을 새 집계로 고친다(AGE-002ㆍSEX-001ㆍFAMILY-001이 후보). 질문 집계가 바뀌면
   `question_relevance_manual_review`의 재집계 기록도 갱신한다.
4. 배포본 감사와 증거 버전 감사를 마지막에 다시 만들고 전체 테스트를 돌린다.

과거 집계 보고서 15개는 수치와 원래 버전을 보존하고 `current_ruleset_version`ㆍ`current_matching_version`만
새 엔진으로 갱신했다. `examples/pilot_feedback.example.jsonl`은 합성 예제이므로 버전만 바꿨다.
