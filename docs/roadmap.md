# FairPost 제품ㆍ기술 로드맵

기준일: 2026-08-30
대상: v0.3 이후 운영 안정화와 v1.0 진입

## 제품 방향

FairPost는 채용공고의 공정성을 점수화하거나 위반 여부를 판정하는 제품이 아니다.
공고 작성자가 근거 표현, 누락 정보와 추가 확인 질문을 빠뜨리지 않도록 돕는
결정론적 검토 보조 도구로 유지한다.

의사결정 원칙은 다음 순서로 적용한다.

1. 정적 웹ㆍCLI처럼 입력이 기기 밖으로 나가지 않는 경로를 기본으로 둔다.
2. 원격 MCP는 사용자가 명시적으로 선택하는 확장 경로로 분리하고 최소 권한으로 운영한다.
3. 규칙 결과는 사람 검토 질문과 근거를 제공할 뿐 합격ㆍ위반ㆍ공정성 판정을 만들지 않는다.
4. 사람 라벨과 재현 가능한 산출물이 없는 정밀도ㆍ재현율 주장은 출시 근거로 사용하지 않는다.
5. 규칙, 매칭 코드, 웹 번들, 배포 런타임과 보고서를 같은 버전 지문으로 묶는다.

## 현재 기준선

- 법령 규칙 19개, 검토 질문 52개, 고정 슬롯 11개
- PRD 코퍼스 600건, train/holdout 420/180 고정 분할과 해시 중복 0
- 확장 train 2,310건 PythonㆍJavaScript 결과 불일치 0
- 공개 원격 MCP는 `check_job_posting`, `next_review_question` 읽기 전용 2도구
- 원격은 Bearer 인증 여부와 관계없이 읽기 전용이며 로컬 MCP만 답변 저장 도구를 노출
- 현재 규칙ㆍ매칭ㆍ런타임 소스 지문을 Vercel 운영 배포에서 대조
- 공식 MCP Inspector 2.4.0으로 현재 Bearer 운영 엔드포인트의 도구 조회ㆍ호출 성공
- 사람 홀드아웃 라벨은 아직 없으며 G1ㆍG2는 미측정
- 민간 목적표본은 단일 출처이므로 다양성 감사가 `alert`

최신 수치는 `reports/build_artifact.json`, 운영 상태는
`reports/vercel_deployment_audit.json`을 기준으로 한다.

## 우선순위

### P0 — v1.0 전에 반드시 해결

| 과제 | 완료 조건 | 담당 역할 |
|---|---|---|
| 봉인 홀드아웃 사람 라벨 | 공공 90건ㆍ민간 90건을 독립 검토하고 완전성ㆍ해시 검증 통과 | 평가 운영자ㆍ도메인 검토자 |
| G1ㆍG2 성능 게이트 | `tools/evaluate.py --enforce-targets`로 G1 정밀도 0.90 이상, G2 재현율 0.85 이상을 사람 라벨에서 입증 | 평가 엔지니어 |
| 민간 출처 다양화 | 단일 출처 지배 경보를 해소하거나, 해소 불가 시 적용 범위를 명시적으로 축소 | 데이터ㆍ공정성 담당 |
| 0건 관찰 규칙 정책 | 후보 0건을 정밀도 실패와 분리해 `coverage_gap`으로 기록하고, 추가 출처ㆍ표적 표본으로 최소 관찰 수를 채우기 전 성능 주장을 금지 | 평가ㆍ데이터 담당 |
| 운영 CI 증거 | GitHub CI와 법령 스냅샷 감사의 실제 성공 실행을 커밋에 연결 | 릴리스 엔지니어 |
| 실제 클라이언트 승인 | 현재 배포의 읽기 도구 조회ㆍ호출을 공식 외부 클라이언트로 검증하고 배포 감사 해시에 결합(현재 충족) | 통합 담당 |
| 릴리스 동결 | 위 조건을 만족한 커밋에 v1.0 태그, 소스 동등성 검증, 정확한 패키지 해시를 부여하고 필요 시 sdist 시각 메타데이터까지 고정 | 릴리스 책임자 |

P0 중 하나라도 충족하지 않으면 자동 테스트 통과만으로 v1.0 성능 완료를
주장하지 않는다.

### P1 — 운영 품질 강화

- 파일럿 피드백은 질문별 유용성ㆍ이해도와 실제 수정 행동을 분리해 집계한다.
- 민간 모니터링은 snapshot→익명 audit→drift→로컬 review queue 사이클을
  정기 실행하고 규칙별 사람 검토 정밀도를 누적한다.
- 후보가 0건인 규칙은 임의 정밀도를 부여하거나 합격 처리하지 않고, 출처 보강 전까지 관찰 증거 없음으로 유지한다.
- 엔진 성능 보고서는 train-only 개발 벤치마크로 유지하고 운영 SLA와 구분한다.
- 새 규칙은 보호 문맥, 제한 문맥, Unicodeㆍ줄바꿈, Pythonㆍ웹 parity 회귀 사례를
  함께 추가해야 병합할 수 있다.
- 공개 MCP의 도구ㆍ입력 스키마 확대는 개인정보 영향과 최소 권한 검토를 먼저 통과해야 한다.
- Claude 호환 익명 경로는 별도 opt-in, 사용량 제한ㆍ남용 모니터링, 원문 전송 고지를 갖추기 전에는 공개하지 않는다.
- 원격 답변 저장은 사용자별 인증 주체와 조직 권한 결합, 보존ㆍ삭제ㆍ암호화 정책이 갖춰지기 전에는 도입하지 않는다.

### P2 — 사용성ㆍ확장

- 현재 UI 구조에 대한 데스크톱ㆍ모바일 시각 검증을 다시 수행한다.
- 질문 근거와 대체 문구를 수정 작업 순서에 맞춰 내보내는 접근성 높은 보고서 형식을 제공한다.
- 조직별 정책 확장은 `FAIRPOST_LOCAL_RULES_PATH`의 consensus 질문 범위 안에서
  버전 관리하며 국가법령 근거를 임의로 덮어쓰지 못하게 유지한다.
- 추가 언어ㆍ문서 형식은 한국어 원문 offset과 법령 근거 정확도를 훼손하지 않는
  별도 실험 트랙에서 검증한다.
