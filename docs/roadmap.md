## 제품 방향

FairPost는 채용공고의 공정성을 점수화하거나 위반 여부를 판정하는 제품이 아니다.
공고 작성자가 근거 표현, 누락 정보와 추가 확인 질문을 빠뜨리지 않도록 돕는
결정론적 검토 보조 도구로 유지한다.

의사결정 원칙은 다음 순서로 적용한다.

1. 정적 웹ㆍCLI처럼 입력이 기기 밖으로 나가지 않는 경로를 기본으로 둔다.
2. 원격 MCP는 사용자가 명시적으로 선택하는 확장 경로로 분리하고 최소 권한으로 운영한다.
3. 규칙 결과는 사람 검토 질문과 근거를 제공할 뿐 합격ㆍ위반ㆍ공정성 판정을 만들지 않는다.
4. 사람 라벨과 재현 가능한 산출물이 없는 정밀도ㆍ재현율 주장은 출시 근거로 사용하지 않는다.
5. 규칙, 매칭 코드, 웹 번들, 배포 런타임과 보고서를 같은 버전 지문으로 묶는다.

수치는 보고서 날짜와 함께 읽는다. `reports/build_artifact.json`은 2026-08-31 기준선(테스트 893개)이고,

  다시 묶을지는 라벨링 소유자가 정하며, 착수 계획은 동결 확정 때 현재 버전으로 다시 만드는 일정으로 잡았다.
- 라벨링 담당자는 아직 정해지지 않았다. 역할ㆍ배분, 2026-10-23에 다시 짠 일정(10/30까지 배정되면 11/02 train 검토 시작,
  2027-01 홀드아웃 평가)과 결정 필요 항목의 제안값은 [사람 라벨링 착수 계획](labeling-kickoff.md)에 있으며, 배정이 확정되면
  이 절에 기록한다. 이중 검토 병합과 일치율 계산은 `tools/merge_dual_review.py`로 한다.

참고: 릴리스 보고서 도구(`tools/build_release_report.py`)의 strict readiness 차단 항목은
6종(`human_holdout_labels`, `private_corpus_diversity`, `current_production_deployment`,
`current_external_client_evidence`, `work24_source_access`, `release_tag`)으로 위 P0 7개와
일대일로 대응하지 않는다. 예를 들어 Work24 출처 접근은 코드 게이트에는 있으나 P0 표에는
별도 행이 없고, 0건 관찰 규칙 정책과 운영 CI 증거는 P0에는 있으나 코드 게이트에는 없다.
공개 원격 MCP의 전역 남용 방어와 실제 채용담당자 파일럿은 P0 표에 없으며, 전자는 익명
공개 경로를 일반 공개하기 전의 조건([Vercel 배포 가이드](vercel-deployment.md)),
후자는 P1ㆍ30/60/90일 실행안에서 다룬다. 이 차이를 v1.0 차단 조건으로 통일할지는 정책 결정이 필요하다.

### P1 — 운영 품질 강화

- `core.review_packet`의 위원장·인사담당·직무전문가·면접위원·정책검토·감사·지원자 대변인 역할을 실제 검토 흐름에 연결한다. NCS 5단계별 이벤트와 공고 fingerprint만 공유하고 원문·지원자 정보는 로컬 경계 밖으로 내보내지 않는다.
- 역할 검토 `note`는 요약과 근거 ID 중심으로 사용하고, 직접식별 패턴을 거부하며, 브라우저 저장 패킷의 ruleset/guidance 버전이 바뀌면 새 패킷으로 분리한다.
- 파일럿 피드백은 질문별 유용성ㆍ이해도와 실제 수정 행동을 분리해 집계한다.
- 민간 모니터링은 snapshot→익명 audit→drift→로컬 review queue 사이클을
  정기 실행하고 규칙별 사람 검토 정밀도를 누적한다.
- 후보가 0건인 규칙은 임의 정밀도를 부여하거나 합격 처리하지 않고, 출처 보강 전까지 관찰 증거 없음으로 유지한다.
- 엔진 성능 보고서는 train-only 개발 벤치마크로 유지하고 운영 SLA와 구분한다.
- 새 규칙은 보호 문맥, 제한 문맥, Unicodeㆍ줄바꿈, Pythonㆍ웹 parity 회귀 사례를
  함께 추가해야 병합할 수 있다.
- 공개 MCP의 도구ㆍ입력 스키마 확대는 개인정보 영향과 최소 권한 검토를 먼저 통과해야 한다.
- Claude 호환 익명 경로는 별도 opt-in, 사용량 제한ㆍ남용 모니터링, 원문 전송 고지를 갖추기 전에는 공개하지 않는다.
- 원격 답변 저장은 사용자별 인증 주체와 조직 권한 결합, 보존ㆍ삭제ㆍ암호화 정책이 갖춰지기 전에는 도입하지 않는다.

### P2 — 사용성ㆍ확장

- 이전 통합 웹 번들은 로컬 Chromium의 데스크톱·모바일에서 검증했다
  (`reports/web_visual_audit.json`, 2026-10-13, 115검사). axe 8상태의 확정 위반은 0이나
  색 대비 자동 판정 일부가 미완료다. 별도 운영 Chromium 검사는 119개 통과·스크린샷
  12장 검토 완료이며 외부·쓰기·POST 요청과 콘솔·페이지 오류는 0건이다
  (`reports/web_production_audit-2026-10-13.json`). 운영에서 axe는 실행하지 않았다.
  최신 추가 작업에서는 로컬·운영 각각 165검사와 스크린샷 20장 검토를 통과했다.
  이번 추가 검증에서 axe는 재실행하지 않았다. UI 구조가 바뀌면 같은 방식으로 갱신한다.
- 질문 근거와 대체 문구를 수정 작업 순서에 맞춰 내보내는 접근성 높은 보고서 형식을 제공한다.
- 조직별 정책 확장은 `FAIRPOST_LOCAL_RULES_PATH`의 consensus 질문 범위 안에서
  버전 관리하며 국가법령 근거를 임의로 덮어쓰지 못하게 유지한다.
- 추가 언어ㆍ문서 형식은 한국어 원문 offset과 법령 근거 정확도를 훼손하지 않는
  별도 실험 트랙에서 검증한다.
