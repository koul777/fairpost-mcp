# DOCX·HWPX·PDF 파일 입력 (선택 기능)

`fairpost check`가 DOCX, HWPX, 글자층이 있는 PDF 파일을 kordoc으로 텍스트로 바꿔 점검함. 변환한 글은 `.txt` 파일과 같은 코드 경로로 엔진에 들어감. 기본 텍스트 경로(LLM·외부 API 호출 없음), 규칙, `matching_version`, JSON 결과 형식은 바뀌지 않음. 정적 웹 앱과 MCP 서버에는 적용되지 않는 CLI 전용 기능임.

## 요약

| 항목 | 내용 |
|---|---|
| 지원 형식 | `.docx`, `.hwpx`, `.pdf`(글자층이 있는 파일). 확장자 대소문자 구분 없음 |
| 거부하는 형식 | `.hwp`(바이너리), `.doc`, 이미지(`.png` `.jpg` `.jpeg` `.webp` `.gif` `.bmp` `.tif` `.tiff`). 한국어 안내 후 종료 코드 2 |
| 변환 도구 | kordoc(npm). 알림에 `kordoc@<버전>`으로 표시 |
| 설치 | `npm install -g kordoc`. Node.js 20 이상 필요 |
| kordoc 찾는 순서 | 환경변수 `FAIRPOST_KORDOC_CLI`(kordoc의 `dist/cli.js` 경로), 없으면 PATH의 `kordoc` |
| 결과 형식 | 텍스트 입력과 같음. 필드 추가 없음. 여러 파일은 기존 `{"source", "result"}` 형식 |
| 변환한 글 확인 | `--converted-text <경로>`가 UTF-8로 저장. 변환하는 파일이 하나일 때만 사용 |

## 실험 결과 (2026-10-24 타당성 확인)

합성 공고 13종에서 만든 문서 213개(DOCX 70, HWPX 57, PDF 86)를 kordoc으로 변환해 점검하고, 원본 텍스트의 점검 결과와 비교함. 문서는 python-docx, python-hwpx, reportlab으로 만든 합성 문서이며 한컴오피스나 Word가 저장한 실제 파일은 포함하지 않음.

- 게이트 동일: finding ID 집합과 개수, `not_found` 슬롯 ID 집합, 질문 ID와 priority가 같음
- 엄격 동일: 게이트에 더해 finding의 section 라벨, finding·질문 인용문, 슬롯 `components_found`, 질문 `trigger_reason`, `counts`까지 같음

| 변환 경로 | 게이트 동일 | 엄격 동일 |
|---|---|---|
| 마크다운 그대로 | 212/213 | 200/213 |
| 마크다운 + 서식 기호 제거·표 규칙 | 213/213 | 213/213 |
| `--plain` 그대로 | 213/213 | 207/213 |
| `--format json` + 블록별 평탄화 (채택) | 213/213 | 213/213 |

차이가 난 현상, 원인, 대응.

| 현상 | 원인 | 대응 |
|---|---|---|
| HWPX 굵은 구절이 `**구절**`로 출력되어 패턴이 끊김(마크다운 경로에서 1건 게이트 차이) | 마크다운 서식 기호 | JSON 블록의 `text`는 서식 기호가 없음 |
| 소제목 칸 + 본문 칸 표에서 section 라벨이 `전체`로 바뀜 | 두 칸을 `a: b` 한 줄로 합침 | 소제목 칸이 짧고 본문 칸이 여러 줄이면 소제목 한 줄과 본문 줄로 나눔 |
| PDF에서 이어진 줄이 한 문단으로 합쳐짐 | kordoc 문단 묶기 | 엔진 결과는 같음. 줄 경계에 기대는 규칙을 추가할 때 재검증 |
| DOCX·HWPX 머리글·바닥글이 본문 첫 줄·끝 줄에 들어감 | 변환기가 본문과 구분 표시하지 않음 | 결과는 같았으나 알림에서 안내함 |

그 밖에 확인한 점.

- 일반 변환 경로(DOCX, HWPX, PDF)는 네트워크에 닿지 않음. 정적 분석과 213건 실행 중 소켓·DNS·fetch 차단 훅 기록 0건으로 확인함
- 변환 시간은 파일당 평균 0.4~0.7초(대부분 Node 시작 시간). 약 40쪽 문서는 1~1.5초
- 이 PC의 kordoc 캐시에 OCR 모델이 있으면 `--ocr` 없이도 이미지 PDF에 로컬 OCR이 자동으로 돌 수 있음. CLI에 끄는 옵션이 없어 빈 `KORDOC_MODEL_CACHE`로 막음
- JSON 평탄화 첫 구현이 중첩 목록(`children`)을 빠뜨려 p04 PDF 6건이 달라졌음. 블록 종류를 빠뜨리면 내용이 조용히 사라지므로 알 수 없는 블록은 오류로 처리함

실험 기록은 로컬 폴더 `tmp/overnight-2026-10-23/kordoc/`(Git 제외)의 `report.md`와 `scripts/`에 있음. 합성 공고 문장은 이 문서에 옮기지 않음.

## 설계

### 변환 경로

1. `cli/document_input.py`의 `convert_document(path)`가 kordoc을 `--format json`으로 실행하고 결과 JSON을 읽음
2. `flatten_kordoc_json(data)`가 블록을 줄로 바꿈. 같은 입력은 항상 같은 텍스트를 만듦
3. 텍스트는 `.txt` 파일과 같은 경로로 `engine.check`(또는 `--review-packet`)에 들어감
4. 변환 결과를 담은 `info`에는 `source_format`, `converter`(`kordoc@<버전>`), `text_sha256`, 읽지 않은 그림 수, 글자층이 없는 PDF 쪽 목록이 있음. CLI 출력 JSON에는 넣지 않고 stderr 알림에만 씀

### 블록 평탄화 규칙

| 블록 | 처리 |
|---|---|
| 문단, 제목, 목록 | 줄 하나. 목록의 `children`은 부모 다음에 재귀로 이어서 출력 |
| 표의 2열 행, 왼쪽이 소제목 칸(16자 이하, `:` 없음, 문장 끝말 없음 또는 `1. 항목` 꼴)이고 오른쪽이 여러 줄 | 소제목 한 줄 + 본문 줄. PDF는 줄바꿈으로 갈라진 본문 줄을 문장 끝이나 목록 기호가 나올 때까지 다시 이음 |
| 표의 그 밖의 2열 행 | `a: b` 한 줄 |
| 표의 3열 이상 행 | 비지 않은 칸을 공백 하나로 연결 |
| 표 캡션 | 표 앞(`captionBelow`이면 뒤)에 한 줄 |
| 각주(`footnoteText`) | 해당 블록 다음에 `(주: ...)` 줄 |
| 그림(`image`) | 글자를 읽지 않음. 개수만 세어 알림에 표시 |
| 구분선(`separator`) | 내용 없음 |
| 그 밖의 블록 종류 | 오류로 처리하고 변환을 중단함. 내용을 조용히 버리지 않음 |

각주, 캡션, 그림 처리는 실험에 쓴 합성 문서에 없던 경우이며, 실험 결과(213/213)는 이 부분을 검증하지 않음. 실험 평탄화기와 같은 입력(213개 JSON)에서 출력이 글자 단위로 같음을 따로 확인함.

### 실행 격리

| 항목 | 방식 |
|---|---|
| 실행 | `node <kordoc의 dist/cli.js> <절대경로> --format json --no-images --silent -o <임시 파일>`. 인자 목록으로 실행하고 셸을 쓰지 않음. `.cmd`·`.ps1` 실행 파일은 실행하지 않음 |
| 경로 찾기 | Windows는 npm 실행 파일 옆 `node_modules/kordoc/dist/cli.js`, POSIX는 링크를 해석. 실행 파일은 위치를 찾는 데만 쓰고 실행하지 않음 |
| 환경변수 | 현재 환경의 복사본에 `KORDOC_OFFLINE=1`, `KORDOC_MODEL_CACHE=<새 빈 임시 폴더>`. 모델 내려받기와 자동 OCR을 막음 |
| 호출하지 않는 것 | OCR 옵션, `watch`, `setup`, `models` 하위 명령 |
| 프로세스 | 표준 입력 닫음, 제한 시간 120초, Windows는 `CREATE_NO_WINDOW`로 콘솔 창 없음 |
| 임시 파일 | 출력 폴더와 빈 캐시 폴더를 매번 만들고 끝나면 지움 |
| 사전 거부 | 암호화된 HWPX(`META-INF/manifest.xml`에 `encryption-data`)와 OLE2 바이너리(HWP, DOC, 암호 걸린 Office)는 kordoc을 실행하기 전에 거부함. kordoc이 이런 파일에서 Windows PowerShell로 한컴오피스 COM 대체 경로를 쓰기 때문 |

### 오류 처리

모든 오류는 stderr에 한국어로 쓰고 종료 코드 2를 반환함. 파일별 오류는 `fairpost: <파일>: <메시지>`, 옵션 오류는 `fairpost: <메시지>` 형식이며 stdout에는 아무것도 쓰지 않음.

| 상황 | 동작 |
|---|---|
| kordoc 또는 Node.js 없음 | 설치 안내(`npm install -g kordoc`, `FAIRPOST_KORDOC_CLI`) |
| kordoc 종료 코드가 0이 아님 | 종료 코드와 kordoc 자체 오류 한 줄을 표시(암호 PDF, 손상 파일 등) |
| 제한 시간 초과 | 중단 후 시간을 표시 |
| 스캔본·이미지 PDF(`isImageBased`) | "스캔본·이미지 PDF는 지원하지 않습니다" |
| 변환한 글이 비어 있음 | 빈 문서이거나 그림뿐인 문서라고 안내 |
| 파일 내용이 DOCX·HWPX·PDF가 아님 | kordoc이 판별한 형식을 표시(확장자만 바꾼 HWP, XLSX 등) |
| 알 수 없는 블록 종류, 구조 이상 | 변환 중단 |

일부 쪽만 글자층이 없는 PDF는 읽은 쪽만으로 점검하고, 읽지 못한 쪽 번호를 알림에 표시함.

### 알림과 변환한 글

변환한 파일마다 stderr에 알림을 씀. 알림에는 변환 도구 버전, 인용문과 위치가 변환한 글 기준이라는 점, 머리글·바닥글이 섞일 수 있다는 점이 들어감. `--converted-text <경로>`는 같은 텍스트를 UTF-8(BOM 없음, 줄바꿈 LF)로 저장하므로 저장한 파일을 다시 점검하면 위치가 같음. 입력 파일과 같은 경로, 변환 파일이 둘 이상인 경우, 변환할 파일이 없는 경우는 변환 전에 거부함.

## 한계

- HWP 바이너리는 시험하지 못해 지원하지 않음. 한글에서 HWPX나 PDF로 저장해야 함
- 스캔본·이미지 PDF와 이미지 파일은 OCR을 쓰지 않으므로 지원하지 않음. 그림 속 글자는 점검하지 않음
- 암호 PDF와 암호화 HWPX는 지원하지 않음
- 한컴·Word가 저장한 실제 파일의 글상자, 도형, 각주, 2단 편집, 자동 번호 체계, 입력 필드는 합성 문서에 없었으므로 확인되지 않음
- 줄 경계에 더 민감한 규칙이 생기면 PDF 줄 합침 차이가 게이트 차이로 번질 수 있음. 이 경우 재검증 필요
- 머리글·바닥글은 본문과 구분되지 않음

## 시험

- `tests/test_document_input.py`: 평탄화 단위 시험(문단, 제목, 중첩 목록, 표 3종, PDF 줄 합침, 각주, 알 수 없는 블록, 결정성), 가짜 kordoc(Node 스크립트)으로 래퍼 시험(성공과 격리 환경변수, 비정상 종료, 이미지 PDF, 빈 출력, 시간 초과, 못 찾음), CLI 시험(DOCX 경로가 같은 텍스트의 `.txt`와 같은 JSON, `.hwp` 등 거부, `--converted-text`)
- 실제 kordoc과 python-docx가 있을 때만 도는 선택 시험 1개. 둘 중 하나라도 없으면 시험 목록에 넣지 않음(CI 포함). Linux CI의 릴리스 보고서는 건너뛴 시험이 하나라도 있으면 실패하기 때문
