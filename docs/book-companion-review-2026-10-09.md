## 사전 검토에서 정한 보완 우선순위

아래 근거는 구현 전 상태의 기록이다. 네 항목 모두 이번에 구현·검증했으며, 현재 결과는 마지막 절과 구현 보고서를 참조한다.

### 1. 기본 화면에서도 네 관점의 질문을 다룬다

근거: web/app.js의 renderEasy()는 표현·누락 안내를 표시한 뒤 질문은 전문가 모드에 있다고 안내한다. 질문 데이터에는 네 관점이 이미 있지만 기본 사용자 흐름에 드러나지 않는다.

보완: 쉬운 모드에서 분배(기회·요건), 절차(기준·재검토), 대인(존중·목소리), 정보(설명·접근)의 의미를 짧게 소개하고 해당 공고의 질문에 연결한다. 관점별 점수나 초록색 통과 표시는 만들지 않는다. 관련 표현이 없더라도 운영 질문은 남을 수 있음을 보여 준다. 기존 질문과 답변 상태를 재사용하여 같은 질문에 중복된 ID나 서로 다른 답변을 만들지 않는다.

검증: AI 채용 예시와 일반 채용 예시에서 기본 화면의 질문을 읽고 답할 수 있어야 한다. 모드 전환 시 답변이 유지되고, 문구를 수정한 후 기존 결과를 최신 결과로 복사하지 못하게 하는 경계가 유지되어야 한다.

### 2. 로컬 프로그램을 첫 실행 경로로 둔다

근거: README의 첫 권장 경로는 공개 웹이며 로컬 화면은 연결형 로컬 웹·MCP로 소개된다. run_fairpost_web.bat은 서버만 실행하고 브라우저는 자동으로 열지 않는다. CLI에는 web 하위 명령이 없다. Python 로컬 런타임과 설치용 웹 자산은 이미 존재한다.

보완: 독자용 제품 이름과 기본 설명은 FairPost 채용공고 검토 프로그램으로 제시한다. Windows 실행 파일 및 간단한 로컬 실행 명령에서 화면까지 연결하고, 의존성 누락·포트 충돌을 이해할 수 있게 안내한다. 기존 명령과 MCP 연결은 호환성을 유지한다. 기본 화면 사용에 MCP 클라이언트나 AI 키를 요구하지 않는다. 서버는 루프백 주소로 제한하고 기존 동일 출처 보호를 유지한다.

검증: 소스 체크아웃과 설치 패키지의 웹 자산 탐색, 기본 실행, 포트 오류, 명시적 브라우저 자동 열기 옵션, 기존 CLI/MCP 회귀를 확인한다.

### 3. 사람의 검토가 다음 행동으로 이어지게 한다

근거: 질문별 답변과 역할 검토 기록은 이미 있으나 전문가 모드에 배치되어 있다. 질문 답변은 분석 메모리에, 역할 기록은 브라우저 저장소에 남아 보관 범위가 서로 다르다.

## Orca 전달 실패와 복구

초기 감사 때의 app.running=false / stale_bootstrap은 연결 전의 관찰이다. 이후 공식 RuntimeClient로 연결하여 실제 작업을 수행했으므로 현재 차단 상태가 아니다. 초기 오류 원문은 tmp/book-review/audit-initial-blocked-excerpt.md에 보존했다.

작업자 네 명의 공식 worker_done은 runtime_access_denied / EPERM으로 전달되지 않았다. Full Access 전환이나 작업자 완료 위조를 하지 않았다. 최종 artifact 수용 뒤 scoped worker-list와 worker-read로 마지막 turn과 activity=done을 확인하고 설치된 recovery-and-cleanup 계약의 worker-abandon을 실행했다. 실제 receipt는 abandoned / processAction=none이며 Task는 실패한 전달이라는 이유로 failed 처리했다. 자동 보존은 worker-abandon의 문서화된 fallback 동작이다. 코디네이터가 이를 사용자 보존 지시로 잘못 해석하여 추가 worker-retain을 호출했다. 그 receipt의 reason=user_requested는 실제 사용자 요청을 뜻하지 않으며, 추가 호출도 processAction=none이었다. 터미널은 유지했고 reclaimable 작업자는 0개다. 산출물 완료와 프로토콜 전달 실패는 서로 다른 상태다.

책 QR의 실제 목적지·최종 인쇄 연결은 확인하지 않았으며 편집부의 인쇄 전 확인 항목으로 남는다. 현행 외부 배포나 법률 상태를 새로 확인한 작업은 아니다.
