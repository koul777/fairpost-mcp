## 원칙과 제약

1. 점수ㆍ등급ㆍ판정은 도입하지 않는다. 기본 점검은 결정론적이고 외부 호출이 없다.
2. **규칙 동결 후보 기간**(로드맵 2026-10-04)이므로 탐지 범위를 넓히는 패턴은 추가하지 않는다.
   허용하는 탐지 변경은 오탐을 줄이는 보호 문맥ㆍ제외, 그리고 확인된 안내를 놓쳐 생기는
   부재 오탐(“확인되지 않음” 오표시) 수정뿐이다. 변경 뒤 새 규칙셋ㆍ매칭 버전을 로드맵 표에 기록한다.
3. Python 엔진과 `web/engine.js`는 같은 변경을 함께 받는다. `web/data.js`는 생성물이다.
4. 의도된 결정은 유지한다: `check_job_posting` 평문 출력과 4구역 질문 묶음, Vercel 답변 저장의
   설정 오류 응답, 원격 저장 도구 비노출, Bearer 실패 시 닫힘, `/book` 임시 리디렉션,
   공통 체크리스트 질문 7개, 규칙당 finding 1개.
5. 봉인 홀드아웃은 열람하지 않는다. 코퍼스는 train 분할만 집계 목적으로 사용한다.

1. A → C → B → D 순서로 병합하고 `web/data.js`를 다시 생성한다.

3. 로드맵 동결 표에 새 규칙셋ㆍ매칭 버전을 기록한다.

5. E가 문서 수치를 확정 값으로 맞춘다.
